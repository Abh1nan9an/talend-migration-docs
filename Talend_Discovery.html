Key messages

  • Salesforce is the hub. 49 of 50 packages read or write Salesforce through the SOAP data API with username/password logins; each of the 19 integration users becomes an OAuth2 connection in Integration Suite.
  • SAP is only reached through SAP PI. 21 packages call 7 PI SOAP services and 7 consume files PI drops on a Windows share. Receiver systems behind PI are not visible in Talend.
  • Windows shares are an integration transport in 30 packages. Integration Suite cannot reach them: SFTP via Cloud Connector or direct APIs replace them.
  • Complexity is concentrated in the service-order family, which exists in parallel variants. Confirming the live variant removes a large part of the effort.
  • 50 packages become about 58 iFlows. Variants are consolidated; file dispatchers split per message type; shared sub-jobs become reusable ProcessDirect iFlows.

    Salesforce modernization

    The Talend jobs use 63 Salesforce objects, 52 of them custom. Most belong to a legacy field-service model (the SC… objects) that predates Salesforce Field Service. Rebuilding the interfaces is the moment to decide whether the iFlows target those objects or standard Salesforce content, and to modernize how the integrations call Salesforce.

    How to use this in the migration

    • Do not couple the changes by default. Migrate interfaces on the existing objects unless the Salesforce team is already moving to Field Service; otherwise each interface is built twice.
    • Adopt the operation patterns now: OAuth, relationship queries, sObject Collections, upsert instead of delete-and-reload, Integration Suite monitoring and value mappings.
    • If the data model moves, go by domain: service execution, then installed base and contracts, then parts and logistics. Decide before the service-order redesign wave.
    • Replace polling with events where Salesforce is the source: record-triggered Flow or Change Data Capture publishing to Integration Suite.

      Next steps

      Recommended sequence

      1. Before wave 1: Cloud Connector, SFTP instead of shares, Salesforce OAuth, PI access; confirm live variants and drafts.
      2. Wave 1 (Simple · Migrate): rebuild on the two templates already built (Salesforce → SAP via PI, SAP via PI file → Salesforce).
      3. Wave 2 (Medium · Adapt): after routines and custom Java are ported into shared script collections.
      4. Wave 3 (Complex · Rework, Very complex · Redesign): service-order family and Gessat, shared sub-jobs as ProcessDirect iFlows.
      5. Every interface: prove parity against Talend_Jobmonitor__c, TMC logs and archived files before cut-over.

      Needed from the client

      • TMC task list: schedules, context values per task, run history and volumes.
      • SAP PI Integration Directory for the 7 service interfaces and the PI file channels.
      • Project routine sources (StringMod, TDIData).
      • Plans for SAP PI and the P:\Services shares; SFTP endpoints for partners, Gessat and Speos.
      • Confirmation of live variants and draft (0.x) packages.
      • Salesforce team: Field Service licences and roadmap, object metadata and record volumes for the SC… objects.
